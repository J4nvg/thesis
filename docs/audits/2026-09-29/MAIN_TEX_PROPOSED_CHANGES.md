## 0b. How far to trust the Chronos-2 top 15 (read before writing §6)

Both models have a full top 15 with positive importance, but they differ in reliability:

- **Global CatBoost-Tweedie**: 427 of 442 features have positive permutation importance (sklearn, 5 real repeats).
  The 15th value (0.0088) is ~100x the largest negative value (-0.00009): the top 15 is well above noise.
- **Chronos-2 fine-tuned**: only 60 of 112 covariates are positive, 51 are negative, and the most negative is
  -0.0014 while the 15th-ranked is +0.0008. Only the top 7 (all weather) exceed the size of the largest negative
  value. The reported `stdev` is 0 for 101 of 112 features because AutoGluon's 5 "shuffle sets" are the SAME shuffle:
  `feature_importance(random_seed=123)` passes one seed to the permutation transform, which re-creates
  `RandomState(123)` on every call, and with 20 regions <= `subsample_size=50` every iteration uses all items
  (`autogluon/timeseries/trainer/trainer.py` ~l.880-930, `utils/features.py` ~l.465-477). The thesis file
  (`results/chronos2/feature_importance_chronos2_ft.csv`) has the same property. So it is one permutation, with
  no uncertainty estimate; ranks below ~7 are not distinguishable from noise.
- Suggested wording (§6) therefore restricts the claim to the leading weather block. A proper fix is a cluster job
  with a different seed per shuffle set (e.g. loop `random_seed=42+i`, `num_iterations=1`, and average), not run.
